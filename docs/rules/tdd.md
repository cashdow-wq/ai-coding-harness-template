# TDD Rule

Use test-first workflow when the task is suitable.

## Preferred Flow

1. Understand expected behavior.
2. Add or update a failing test.
3. Implement minimal code.
4. Run test.
5. Refactor.
6. Run test again.

## When TDD Is Optional

TDD is optional for:

- pure documentation changes
- small config changes
- exploratory investigation
- UI-only changes without test setup

## Rule

If tests are not added, explain why.
